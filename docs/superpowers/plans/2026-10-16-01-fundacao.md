# Fundação e segurança — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Inicializar o aplicativo novo com banco exclusivo, gravações recuperáveis, auditoria e PIN.

**Architecture:** Infraestrutura mínima comum, sem copiar o modelo de dados legado. Transações e autorização são contratos dos serviços, independentes do Tkinter.

**Tech Stack:** Python 3, Tkinter/ttk, SQLite, unittest e XlsxWriter já incluído no projeto.

**Spec:** [Especificação aprovada](../specs/2026-10-16-salva-ai-novo-design.md). Ler também o [plano geral](2026-10-16-salva-ai-plano-geral.md).

## Global Constraints

- Python 3, Tkinter/ttk e SQLite; Windows prioritário; funcionamento offline.
- Um dispositivo, um operador e aproximadamente 20 produtos.
- Venda em unidades inteiras de produtos fechados; sem receitas, doses ou ingredientes.
- Dinheiro, Pix, débito e crédito apenas à vista; um meio por venda.
- Sem fiado, descontos manuais ou pagamentos divididos.
- Promoções por quantidade são a exceção de preço explicitamente autorizada.
- Sem servidor, dependência de internet para vender ou serviços pagos obrigatórios.
- Sem emissão fiscal, conciliação bancária ou promessa de lucro contábil oficial.
- Sem merge, release ou publicação externa sem autorização.
- Banco vazio e diretório próprio; nunca abrir o banco antigo nem usar dados reais nos testes.
- Operações e auditoria atômicas; dinheiro exato, custódia separada de receita.
- Nenhuma contagem de testes planejados equivale a testes já executados.
- Checkout já isolado: não criar worktree sem pedido explícito; implementação em branches de funcionalidade derivadas da branch de desenho.



## Review Focus

- Reinício após comando confirmado: mesmo resultado, nenhum evento adicional — tarefa 1.
- Banco legado selecionado por engano: recusa sem escrita — tarefa 1.
- Hora retrocedendo durante espera do PIN: não liberar tentativa antecipada — tarefa 2.
- Tentativa de reutilizar autorização para outra ação: recusar — tarefa 2.
- Janela fechada durante operação: encerrar conexão e preservar dados — tarefa 3.

### Tarefa 2: PIN e recuperação sem segredos persistidos

**Interfaces:** `SecurityService(db, clock)`; `setup(pin: str) -> str` retorna chave só uma vez; `authorize(pin: str, action: str) -> AdminGrant`; `consume(grant: AdminGrant, action: str) -> None`; `recover(recovery_key: str, new_pin: str) -> str`. `AdminGrant` contém identificador opaco, ação e validade, e só é emitido pelo serviço.

- [x] **1. Escrever testes que falham.** PIN de seis dígitos, parâmetros PBKDF2 do plano geral, cinco erros e bloqueio inicial de 30 s. Testar expiração/uso único, ação diferente, reinício durante bloqueio, relógio retrocedendo, chave usada novamente e ausência de PIN/chave em linhas de banco, auditoria e logs.

```python
key = self.security.setup("681942")
grant = self.security.authorize("681942", "expense.delete")
with self.assertRaises(AuthorizationError):
    self.security.consume(grant, "stock.adjust")
new_key = self.security.recover(key, "729516")
self.assertNotEqual(key, new_key)
with self.assertRaises(AuthorizationError):
    self.security.recover(key, "123456")
```
